## 2. Descripción funcional
* **Descripción:** EDUCACION OS no debe sentirse como un "software donde entras a hacer la tarea". Implementa paradigmas de *Invisible UI* (Interfaz Invisible). El sistema detecta el contexto del alumno (Geolocalización, Hora del día) y envía micro-interacciones accionables directo a sus notificaciones del celular o smartwatch, permitiéndole responder preguntas de opción múltiple sin abrir la aplicación.
* **Objetivo:** Reducir la fricción del aprendizaje a cero. Convertir el repaso espaciado en un hábito subconsciente, integrado en la vida diaria del estudiante.
* **Alcance:** Progressive Web App (PWA), Notificaciones Push Enriquecidas (Actionable Push), Integración con APIs de SO Móvil.
* **Actores:** Estudiante (Receptor), Motor de Notificaciones (Emisor).

## 3. Contexto
* **Precondiciones:** 
  1. El alumno instaló la PWA o App Nativa y aceptó permisos de Notificaciones Push.
  2. Motor de Repaso Espaciado activo.
* **Disparador:** El algoritmo determina que es el momento óptimo de la curva de olvido (Ebbinghaus) para repasar un concepto.
* **Postcondiciones:** El estudiante responde directamente desde la pantalla de bloqueo de su teléfono.

## 6. Flujo funcional
### Flujo principal (Actionable Push Notification)
1. El Gemelo Digital (RF-038) determina que Juan olvidará la "Fórmula del Área del Círculo" en 2 horas.
2. Juan está caminando hacia su casa (El teléfono detecta movimiento).
3. El sistema envía una notificación Push enriquecida a su Apple Watch o pantalla de bloqueo de Android: *"Rápido, ¿Cuál es el área de un círculo? A) πr², B) 2πr"*.
4. Juan toca el botón `A)` directamente en la notificación, sin desbloquear el teléfono.
5. El Service Worker de la PWA intercepta la acción, y envía un POST silencioso al backend en background.
6. La pantalla de bloqueo le muestra un checkmark verde ✅ y le otorga 10 Tokens (RF-036). Fin de la interacción (Duración: 3 segundos).

### Flujos de excepción
* **FE-01: Offline Mode:** Si Juan no tiene internet cuando presiona la opción, el Service Worker (IndexedDB) guarda la respuesta en cola y la sincroniza con el LRS (RF-041) apenas el teléfono detecte red 4G/WiFi.

## 8. Reglas de negocio
* **RN-001 (Control de Interrupciones - Do Not Disturb):** El motor jamás debe enviar un micro-push durante horario escolar (8am-3pm) o después de las 9:00 PM, para respetar la higiene del sueño y la atención en clases físicas.
* **RN-002 (Límite de Carga):** Máximo 3 micro-interacciones ubicuas por día. Si el alumno las ignora (las borra de la pantalla), el sistema hace back-off exponencial (espera más días antes de enviar otra).

## 9. Permisos y seguridad
* **Zero-Auth Responses:** Dado que el usuario responde desde la pantalla de bloqueo sin contraseña, el endpoint de respuesta vía Webhook Service Worker debe validar un JWT de uso único y corto alcance (Magic Token) embebido en el Payload del Push, para evitar ataques de manipulación.

## 10. Persistencia
* **Tablas/Colecciones:** Postgres.

## 11. Integraciones
* **Web Push API / Service Workers:** Uso del API estándar de navegadores modernos para manejar `notificationclick` events en background.
* **FCM (Firebase Cloud Messaging):** Para asegurar entrega en Android/iOS.

## 12. Auditoría
* Monitorear el "Drop-off rate". Si las micro-notificaciones son percibidas como Spam por los alumnos y desinstalan la PWA, se debe ajustar el algoritmo.

## 13. Notificaciones
* El Core de este RF es en sí mismo una Notificación interactiva.

## 14. Criterios de aceptación (BDD)
* **CA-01: Manejo Background (Service Worker)**
  * *Given* que el usuario recibe una notificación interactiva
  * *When* presiona un botón de respuesta (`action`) en la notificación
  * *Then* el Service Worker debe procesar el request en background sin abrir la ventana del navegador web, enviando el resultado y cerrando la notificación automáticamente.
* **CA-02: Resiliencia Offline**
  * *Given* el modo avión activado
  * *When* el usuario responde la pregunta cacheada
  * *Then* el Service Worker debe usar Background Sync API para encolar el request y despacharlo en el futuro cuando el evento `online` se dispare.
