# RF-021: Early Warning System (EWS) Proactivo con Plan Sugerido

## 1. Identificación
| Atributo | Detalle |
| :--- | :--- |
| **Código** | RF-021 |
| **Nombre** | Early Warning System (EWS) Proactivo con Plan Sugerido |
| **Módulo** | Inteligencia Artificial / Intervención Psicológica |
| **Tipo** | Sistema de Recomendación Prescriptiva (Prescriptive Analytics) |
| **Versión** | 1.0 |
| **Estado** | AUDITED (Enriquecido) |
| **Prioridad** | Alta |

## 2. Descripción funcional
* **Descripción:** Extensión del Motor Predictivo (RF-016). Una vez que la IA detecta que un alumno está en riesgo crítico de deserción (Predictivo), este módulo entra en acción utilizando LLMs (GPT-4 / Claude) para analizar el contexto cualitativo del estudiante y redactar automáticamente un "Plan de Intervención Sugerido" personalizado para el psicólogo o tutor.
* **Objetivo:** Reducir la fricción del equipo de bienestar. No solo avisar "Se va a ir", sino prescribir "Haz exactamente esto para salvarlo".
* **Alcance:** Generación de plan (Prompts a LLM), guardado del plan como borrador, y registro de feedback del psicólogo.
* **Actores:** Sistema (Analista), Psicólogo/Tutor (Ejecutor).

## 3. Contexto
* **Precondiciones:** 
  1. RF-016 disparó un `risk_score > 0.85`.
  2. Perfil 360° del alumno (RF-015) tiene datos suficientes (notas, asistencia).
* **Disparador:** Inserción de un nuevo perfil en `student_risk_profiles` con nivel `CRITICAL`.
* **Postcondiciones:** Generación de un ticket de intervención en la tabla `intervention_plans` con el texto sugerido por la IA.

## 4. Entradas
| Parámetro | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :---: | :--- |
| `student_id` | UUID | Sí | Alumno en riesgo. |
| `context_payload`| JSON | Sí | Resumen condensado de los últimos 30 días del alumno para el Prompt del LLM (Max 2000 tokens para ahorrar costos). |

## 5. Salidas
| Resultado / Campo | Tipo / Estado | Mensaje |
| :--- | :--- | :--- |
| `suggested_plan` | TEXT | Markdown con: 1. Diagnóstico, 2. Acción inmediata, 3. Tareas a mediano plazo. |
| `intervention_id`| UUID | ID del ticket creado para el psicólogo. |

## 6. Flujo funcional
### Flujo principal (Generación Prescriptiva RAG)
1. El Event Bus capta el evento `EWS_CRITICAL_RISK`.
2. El servicio `InterventionService` compila el `context_payload` (Notas recientes, asistencias, apuntes de profesores).
3. Envía un prompt estructurado al LLM: *"Actúa como un psicólogo educativo senior. Analiza este contexto y genera un plan de retención en 3 pasos..."*
4. La respuesta del LLM es parseada (JSON u objeto estructurado).
5. Se crea un registro en `intervention_plans` asignado al tutor del estudiante, con estado `DRAFT`.
6. Se notifica al tutor: "Plan de Intervención generado para Juan Pérez. Por favor revisar y aprobar".

### Flujos alternativos
* **FA-01: Auto-corrección Humana:** El tutor lee el plan generado por la IA, pero lo edita (ej. cambia el Tono o añade un contexto humano que la máquina no sabía). Al darle "Guardar", se emite un evento de telemetría para hacer fine-tuning futuro de la IA.

### Flujos de excepción
* **FE-01: LLM Timeout / Rate Limit:** Si el proveedor de IA (ej. OpenAI) devuelve un 503 o 429, el sistema entra en Fallback. Se crea el ticket en `intervention_plans` vacío con una etiqueta `[Auto-Plan falló - Redactar manualmente]`.

## 8. Reglas de negocio
* **RN-001 (Human-in-the-Loop):** La IA JAMÁS ejecuta el plan automáticamente (ej. No le manda un correo de reprimenda al alumno sola). El estado inicial es siempre `DRAFT` y requiere que un profesional con licencia (Psicólogo) presione `APPROVED`.
* **RN-002 (Anonimización de Prompt):** Por regulaciones FERPA (RF-020), el `context_payload` que viaja a OpenAI NO puede contener el nombre real ni el DNI del alumno. Se debe usar un alias (`Estudiante_X`) al construir el prompt.

## 9. Permisos y seguridad
* **Políticas RLS:** Solo los usuarios con rol `PSYCHOLOGIST`, `PRINCIPAL` o el Tutor asignado a ese alumno pueden leer la tabla `intervention_plans`.

## 10. Persistencia
* **Tablas/Colecciones:** `intervention_plans`.
* **Soft Deletes:** Los planes de intervención, exitosos o fallidos, nunca se borran. Son material clínico vital.

## 11. Integraciones
* **Motor LLM:** LangChain o Vercel AI SDK conectando a Anthropic Claude 3.5 Sonnet (ideal para razonamiento empático) o GPT-4o.

## 12. Auditoría
* Rastreo del Delta de edición: Se guarda en `audit_logs` la diferencia entre el `ai_suggestion` original y el `final_plan` del humano. Si el humano borra el 90% del plan, indica que el prompt está alucinando o es inútil.

## 13. Notificaciones
* Correo interno al equipo de retención con el enlace directo al ticket de intervención.

## 14. Criterios de aceptación (BDD)
* **CA-01: Privacidad en el Prompt (Data Masking)**
  * *Given* que un alumno se llama "Eduardo Paipay" con DNI "73000000"
  * *When* el `InterventionService` construye el prompt para OpenAI
  * *Then* el string saliente debe haber reemplazado esos datos con "Estudiante Alpha" y el DNI debe ser removido, garantizando cero fuga de PII al proveedor Cloud.
* **CA-02: Human-in-the-Loop Enforcement**
  * *Given* un plan recién generado
  * *When* el tutor intenta cerrarlo como `CLOSED_SUCCESS` directamente
  * *Then* el sistema exige que primero pase por estado `APPROVED` y que el campo `final_plan` no esté vacío.
