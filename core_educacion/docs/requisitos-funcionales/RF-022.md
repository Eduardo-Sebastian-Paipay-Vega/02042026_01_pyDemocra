## 2. Descripción funcional
* **Descripción:** Sistema algorítmico que abandona la educación lineal clásica. Modeliza el currículo (sílabo) como un Grafo Dirigido Acíclico (DAG). Si el estudiante falla repetidamente en un concepto avanzado (ej. Ecuaciones Cuadráticas), el motor recalcula su "Ruta" y lo devuelve automáticamente al nodo raíz fallido (ej. Factorización Básica) inyectando lecciones correctivas antes de dejarlo avanzar.
* **Objetivo:** Personalización masiva. Ningún estudiante tiene el mismo temario; la plataforma muta según el ritmo de dominio del alumno.
* **Alcance:** Evaluación de Nodos, Traversal del Grafo, y alteración de la vista del temario en el frontend.
* **Actores:** Sistema (Motor de Grafo), Estudiante (Sujeto).

## 3. Contexto
* **Precondiciones:** 
  1. El Currículo fue construido como un Grafo de prerrequisitos (RF-001).
  2. El estudiante acaba de terminar una Evaluación (Quiz/Tarea) vinculada a un Nodo Específico.
* **Disparador:** Puntuación menor al umbral de dominio (ej. < 70%).
* **Postcondiciones:** El `student_learning_path` se actualiza. Módulos futuros se bloquean, módulos de nivelación se insertan dinámicamente en el Home del alumno.

## 6. Flujo funcional
### Flujo principal (Re-routing por Deficiencia)
1. El estudiante obtiene 40% en el test de "Trigonometría Básica" (Nodo T1).
2. El `PathingEngine` recibe el evento. Comprueba que el *Threshold* de dominio es 70%.
3. Al fallar, el motor hace una búsqueda en reversa (Reverse DFS) en el Grafo (DAG) de Postgres buscando los "Nodos Prerrequisito" directos (ej. Geometría de Triángulos).
4. El sistema evalúa si el alumno tenía un `mastery_score` antiguo débil en ese prerrequisito.
5. El sistema inyecta una Lección Remedial (Generada por IA o pre-grabada) como paso obligatorio siguiente.
6. La interfaz de usuario del alumno se actualiza animadamente: El camino (roadmap visual) se reorganiza, insertando una "Isla" o parada obligatoria antes del siguiente tema.

### Flujos alternativos
* **FA-01: Fast-Tracking (Adelanto de Genios):** Si en un examen diagnóstico inicial el estudiante saca 100%, el motor hace un "Forward DFS" e invalida (salta) todas las lecciones básicas conectadas, ahorrándole semanas de aburrimiento.

### Flujos de excepción
* **FE-01: Ciclo Infinito (Infinite Loop Protection):** Si el estudiante falla la remediación repetidamente (más de 3 veces), el sistema no lo degrada indefinidamente (creando frustración extrema). Se detiene el motor, se congela el avance, y se dispara una alerta humana al profesor: `Intervención Pedagógica Requerida`.

## 8. Reglas de negocio
* **RN-001 (Ciclos Prohibidos):** Al ser un DAG (Directed Acyclic Graph), está estrictamente prohibido que el Node A requiera al Node B, y el Node B requiera al Node A. Se debe validar esto recursivamente a nivel de Base de Datos al guardar el currículo.
* **RN-002 (Preservación del Ego):** Las lecciones inyectadas por bajo rendimiento NUNCA se rotulan como "Lección para reprobados". Se etiquetan como "Misión de Refuerzo" para proteger la carga emocional del menor.

## 9. Permisos y seguridad
* **RLS:** `student_paths` es estrictamente privada por estudiante (Un alumno no puede ver la ruta mutada de otro para evitar comparaciones tóxicas).

## 10. Persistencia
* **Tablas/Colecciones:** Postgres para relaciones fijas, pero el cálculo del recorrido del grafo idealmente se soporta con Common Table Expressions Recursivas (`WITH RECURSIVE`) de PostgreSQL.

## 11. Integraciones
* **Motor de Reglas:** Lógica puramente interna en NestJS (No depende de APIs externas, es el IP intelectual de la empresa).

## 12. Auditoría
* Telemetría sobre "Rutas más mutadas". Si el 80% de los estudiantes son retrocedidos en el Nodo X, el problema no son los alumnos, es el Nodo X (El profesor lo explicó mal). Genera alerta de "Cuello de botella pedagógico".

## 13. Notificaciones
* No intrusivas. Solo un aviso in-app: "Hemos ajustado tu mapa para ayudarte a dominar mejor este tema."

## 14. Criterios de aceptación (BDD)
* **CA-01: Inserción de Remedial**
  * *Given* que el Node B requiere el Node A, y el umbral es 80%
  * *When* el alumno saca 60% en el Node B
  * *Then* el sistema debe mutar el `active_queue` inyectando un Node A-Remedial antes de permitirle re-intentar el Node B.
* **CA-02: Protección Anti-Ciclo**
  * *Given* que un administrador intenta guardar una dependencia recursiva A -> B -> C -> A
  * *When* se envía el POST al currículo
  * *Then* el validador de Grafos de NestJS rechaza el guardado devolviendo HTTP 422 Unprocessable Entity ("Ciclo detectado en grafo").
