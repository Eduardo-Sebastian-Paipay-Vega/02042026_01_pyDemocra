## 2. Descripción funcional
* **Descripción:** Un motor basado en LLMs (Gemini/OpenAI) que procesa los materiales de un curso (ej. transcripciones de videos o PDFs) y genera variaciones de contenido adaptadas en tiempo real al perfil cognitivo, edad, idioma y ritmo de aprendizaje del estudiante (Digital Twin - DTL).
* **Objetivo:** Automatizar la diferenciación instruccional, reduciendo a cero el esfuerzo del docente para crear múltiples versiones del mismo tema.
* **Alcance:** Modificación de lectura, generación de resúmenes, traducción nativa, y alteración de dificultad léxica en base al perfil del alumno.
* **Actores:** Sistema (Fondo), Estudiante (Consumidor), API LLM (Procesador).

## 3. Contexto
* **Precondiciones:** 
  1. Perfil del estudiante (DTL) inicializado y en memoria.
  2. Material de estudio original subido y procesado (embeddings creados).
  3. Contexto `tenant_id` y permisos RLS vigentes.
* **Disparador:** El estudiante entra a una lección. Si la lección detecta que la distancia semántica entre la dificultad del material y el perfil del alumno es amplia, invoca la adaptación.
* **Postcondiciones:** Se almacena en base de datos una variación de contenido específica (caché por perfil), la cual es entregada al estudiante.

## 4. Entradas
| Parámetro | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :---: | :--- |
| `student_profile` | JSONB | Sí | Extraído del JWT y la tabla de Gemelo Digital. |
| `original_content` | TEXT / MD | Sí | No debe exceder la ventana de contexto del LLM (Chunking). |
| `adaptation_target` | ENUM | Sí | `SIMPLIFY`, `EXPAND`, `TRANSLATE`, `PRACTICAL_FOCUS`. |
| `tenant_id` | UUID | Sí | Validación estricta a nivel JWT. |

## 5. Salidas
| Resultado / Campo | Tipo / Estado | Mensaje |
| :--- | :--- | :--- |
| `adapted_content` | TEXT / MD | "Contenido adaptado generado." |
| `ai_metadata` | JSONB | Tokens usados, modelo empleado, confidence score. |
| `429 Too Many Requests` | HTTP Error | "Límite de adaptación excedido por tenant." |
| `503 Service Unavailable` | HTTP Error | "Fallo de comunicación con proveedor LLM." |

## 6. Flujo funcional
### Flujo principal
1. El frontend carga la lección y envía una petición a `/api/v1/ai/adapt`.
2. NestJS verifica en Redis si ya existe una versión adaptada para el hash de este perfil + contenido (Cache Hit).
3. (Cache Miss) El servicio construye un Prompt estructurado usando System Instructions duras.
4. El servicio orquesta una llamada a la API (OpenAI/Gemini).
5. Se recibe el streaming o la respuesta síncrona.
6. La respuesta se limpia (Sanitización HTML/Markdown para evitar inyecciones).
7. Se guarda la variación en la base de datos `content_variations` asociada al `tenant_id` y al perfil.
8. Se retorna al frontend y se renderiza con animaciones de "AI Generating...".

### Flujos alternativos
* **FA-01: Streaming (Server-Sent Events):** Para evitar bloqueos, el backend devuelve el contenido en chunks vía SSE, permitiendo que el estudiante comience a leer de inmediato.

### Flujos de excepción
* **FE-01: Fallo del LLM:** Si la API devuelve error 500, el sistema hace un fallback silencioso entregando el contenido ORIGINAL y muestra un ligero aviso ("Modo original").
* **FE-02: Inyección de Prompt (Jailbreak):** El sistema pasa el contenido a través de una capa de filtro semántico para asegurar que la adaptación no incluyó sesgos ni violaciones a las reglas del Tenant.

## 8. Reglas de negocio
* **RN-001 (Control de Costos):** Un tenant tiene una cuota máxima de tokens mensuales. Si la cuota se agota, el motor de adaptación se deshabilita temporalmente (fallback al original).
* **RN-002 (Aislamiento AI):** El contexto de adaptación jamás debe mezclar datos o PII (Personally Identifiable Information) de un estudiante con el modelo (Zero-Data Retention agreements con el proveedor LLM).

## 9. Permisos y seguridad
* **Autenticación:** Requerida (Supabase Auth).
* **Autorización:** 
  * RLS en `content_variations`:
    ```sql
    CREATE POLICY "Estudiantes leen variaciones de su tenant" ON content_variations 
    FOR SELECT USING (tenant_id = auth.jwt()->>'tenant_id');
    ```
* **Protección API:** Rate-limiting estricto por IP y `user_id` en NestJS (Throttler).

## 10. Persistencia
* **Tablas/Colecciones:** `content_variations`, `tenant_billing`.
* **Operaciones CRUD permitidas:** Insert (por el sistema), Select (por el estudiante). No hay Update manual.

## 11. Integraciones
* **APIs externas:** Google Gemini API o OpenAI API.
* **Monitoreo:** LangSmith / Datadog para trazar la calidad y latencia de las peticiones LLM.

## 12. Auditoría
* Cada adaptación deduce tokens. Se registra en `tenant_ledger` el costo computacional de la operación para facturación B2B.

## 13. Notificaciones
* Silencioso. El usuario no recibe notificaciones, solo ve una experiencia mágica e invisible.

## 14. Criterios de aceptación (BDD)
* **CA-01: Generación exitosa**
  * *Given* un estudiante con nivel de lectura "Básico"
  * *When* solicita un texto clasificado como "Avanzado Universitario"
  * *Then* el sistema devuelve una versión simplificada y registra el gasto de 500 tokens en el tenant.
* **CA-02: Fallback ante cuota agotada**
  * *Given* un tenant que excedió sus créditos mensuales
  * *When* un estudiante solicita una adaptación
  * *Then* el sistema devuelve el contenido original sin llamar a la API de IA.
