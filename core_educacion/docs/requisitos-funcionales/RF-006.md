## 2. Descripción funcional
* **Descripción:** Sistema de clasificación dinámica que agrupa a los estudiantes por cohortes o cursos y los ordena según los Puntos de Experiencia (XP) acumulados. Soporta actualizaciones en tiempo real y segmentación temporal (Semanal, Mensual, Histórico).
* **Objetivo:** Fomentar la competencia sana y el "Social Proof", impulsando el engagement de los usuarios a través del refuerzo positivo constante.
* **Alcance:** Creación y visualización del leaderboard. Impacta solo en consultas de lectura.
* **Actores:** Estudiante (Visualizador), Sistema (Calculador).

## 3. Contexto
* **Precondiciones:** 
  1. Estudiantes con perfiles activos y puntos de XP en la base de datos.
  2. Contexto de tenant (`tenant_id`) estrictamente cargado.
* **Disparador:** El estudiante accede a la pestaña "Leaderboard" o completa una tarea que cambia su posición.
* **Postcondiciones:** La vista de la tabla de posiciones refleja el ranking actualizado.

## 4. Entradas
| Parámetro | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :---: | :--- |
| `tenant_id` | UUID | Sí | Validado vía JWT. |
| `cohort_id` | UUID | No | Si es nulo, es ranking global del tenant. |
| `period` | ENUM | Sí | `WEEKLY`, `MONTHLY`, `ALL_TIME`. Default: `WEEKLY`. |
| `limit` | INT | No | Default 50. Max 100. (Paginación). |

## 5. Salidas
| Resultado / Campo | Tipo / Estado | Mensaje |
| :--- | :--- | :--- |
| `ranking_list` | JSON Array | Lista de `{ rank, user_id, avatar_url, name, xp }`. |
| `current_user_rank`| JSON | Posición específica del usuario que consulta (ej. Rank 152). |
| `429 Too Many Requests`| HTTP Error | Bloqueo por exceso de llamadas a la vista agregada. |

## 6. Flujo funcional
### Flujo principal (Lectura)
1. El frontend carga la ruta `/leaderboard`.
2. Se envía la solicitud a la API de NestJS (`/api/v1/gamification/leaderboard`).
3. NestJS verifica el caché en Redis.
4. (Cache Hit): Retorna el JSON cacheado inmediatamente.
5. (Cache Miss): Realiza un Query optimizado usando `RANK() OVER (ORDER BY xp DESC)` en la vista materializada de Supabase.
6. Se guarda el resultado en Redis con un TTL corto (ej. 3 minutos).
7. Se devuelve el ranking al cliente.

### Flujos alternativos
* **FA-01: Auto-posicionamiento:** Si el usuario no está en el Top 50, la respuesta incluye un nodo extra al final mostrando su posición exacta y cuántos puntos necesita para subir de puesto.

### Flujos de excepción
* **FE-01: Empates (Tie-breaker):** Si dos estudiantes tienen exactamente el mismo XP, el empate se resuelve ordenando por `updated_at` (quien llegó primero al puntaje queda arriba).

## 8. Reglas de negocio
* **RN-001 (Privacidad):** Si un estudiante marca su perfil como `is_private = true` en sus configuraciones, aparecerá en el Leaderboard como "Estudiante Anónimo" conservando su rango, pero sin foto ni nombre.
* **RN-002 (Caché obligatorio):** Debido a que el cálculo de `RANK()` en tablas grandes es costoso (CPU intensive), los rankings NUNCA se consultan directamente en tiempo real a Postgres, siempre a través de Redis (Eventual Consistency).

## 9. Permisos y seguridad
* **Autenticación:** Requerida (JWT).
* **Autorización:** 
  * RLS en las tablas subyacentes:
    ```sql
    CREATE POLICY "Usuarios ven rankings de su tenant" ON student_profiles 
    FOR SELECT USING (tenant_id = auth.jwt()->>'tenant_id');
    ```

## 10. Persistencia
* **Tablas/Colecciones:** `student_profiles` (tabla base), `leaderboard_weekly_mat_view` (Vista Materializada).
* **Operaciones CRUD permitidas:** Solo SELECT. La vista se actualiza vía CRON de pg_cron o Trigger diferido.

## 11. Integraciones
* **Redis:** Upstash o Memorystore (GCP) para el ranking en memoria (`ZREVRANGE` es ideal para sorted sets).

## 12. Auditoría
* Monitoreo de consultas lentas (`pg_stat_statements`). Si el recálculo toma > 5 segundos, dispara una alerta en Datadog.

## 13. Notificaciones
* Si un estudiante entra al "Top 3" de la semana, se le envía un correo felicitándolo el día domingo a las 23:59 hrs (Cierre de ranking).

## 14. Criterios de aceptación (BDD)
* **CA-01: Resolución de Empates**
  * *Given* que los usuarios A y B tienen 500 XP
  * *When* el sistema calcula el `RANK()`
  * *Then* el usuario que consiguió los 500 XP primero debe estar en un rango numéricamente superior (ej. Rank 1 vs Rank 2).
* **CA-02: Filtro de Privacidad**
  * *Given* que el usuario C (Rank 5) activó el modo privado
  * *When* otro estudiante visualiza el Leaderboard
  * *Then* en el puesto 5 debe decir "Estudiante Anónimo" y la foto debe ser un avatar genérico.
