## 2. Descripción funcional
* **Descripción:** Panel de Business Intelligence exclusivo para el Director (Tenant Owner) que le muestra en tiempo real cómo está rindiendo su colegio (en promedios académicos, deserción, morosidad financiera) frente al **Promedio Nacional o Regional Anónimo** de todos los demás colegios que usan EDUCACION OS.
* **Objetivo:** Entregar un inmenso valor añadido al B2B. Los directores siempre quieren saber "¿Estoy mejor o peor que la competencia?". Esto actúa como herramienta de retención del software.
* **Alcance:** Consolidación anónima inter-tenant, visualización de cuartiles/percentiles.
* **Actores:** Director / Inversor (Visualizador), Data Warehouse Central (Procesador).

## 3. Contexto
* **Precondiciones:** 
  1. Base de datos global con múltiples tenants activos (volumen estadísticamente significativo).
  2. Tablas OLAP consolidadas a nivel Global (Cross-tenant).
* **Disparador:** El Director accede a la pestaña "Benchmarking Institucional".
* **Postcondiciones:** Renderizado de gráficos comparativos (`Tu Colegio` vs `Promedio Regional`).

## 4. Entradas
| Parámetro | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :---: | :--- |
| `tenant_id` | UUID | Sí | ID del colegio solicitante. |
| `segment` | ENUM | No | Filtro: Comparar contra `SAME_CITY`, `SAME_SIZE_TIER`, `NATIONAL`. |
| `metric` | VARCHAR | Sí | Ej. `DROPOUT_RATE`, `MATH_AVG`, `LATE_PAYMENTS`. |

## 5. Salidas
| Resultado / Campo | Tipo / Estado | Mensaje |
| :--- | :--- | :--- |
| `tenant_value` | FLOAT | El valor crudo del colegio solicitante (ej. 14.5). |
| `benchmark_avg` | FLOAT | El promedio del segmento (ej. 12.3). |
| `percentile_rank`| INT | En qué percentil se ubica (ej. Top 15%). |

## 6. Flujo funcional
### Flujo principal (Agregación OLAP)
1. El request del Director llega al API Gateway.
2. NestJS redirige la consulta (vía gRPC o HTTP interno) a un microservicio exclusivo de analíticas globales (BigQuery o ClickHouse) para no saltarse accidentalmente las barreras de RLS en Postgres (Peligroso).
3. BigQuery ya tiene pre-calculadas (Cron nocturno) las medias, medianas y desviaciones estándar de todos los colegios por ciudad y por tamaño (Tier), sin datos personales.
4. Extrae la métrica específica del `tenant_id` que solicita, y la pone lado a lado contra el agregado global anónimo del cluster.
5. Se devuelve un JSON de series de tiempo al frontend.
6. El Dashboard renderiza un gráfico de Área donde la línea azul gruesa es el colegio, y la franja gris debajo es el mercado.

### Flujos de excepción
* **FE-01: Exposición Competitiva (Threshold de Privacidad):** Si en la ciudad "Arequipa" solo hay 2 colegios usando el software, el Director del Colegio A podría inferir exactamente los datos del Colegio B (Su competencia directa). Regla matemática: El benchmarking se deshabilita para cualquier segmento (`segment`) que tenga menos de 5 colegios (k-anonymity compliance).

## 8. Reglas de negocio
* **RN-001 (K-Anonymity):** Estricto blindaje. Nunca revelar el nombre de los otros colegios. Nunca mostrar promedios de grupos de menos de N=5 instituciones. (Evita que el software sea usado como herramienta de espionaje corporativo).
* **RN-002 (Incentivo Positivo):** Si el colegio está por debajo del promedio en retención de estudiantes, el panel levanta sugerencias automáticas de *Cross-Selling*: "Estás 10% por debajo del mercado en deserción. ¿Deseas activar el módulo EWS Predictivo (RF-016) por $99/mes extra?".

## 9. Permisos y seguridad
* **Aislamiento de BD:** A nivel Postgres (Sistema Transaccional), el Row Level Security (`tenant_id = auth.jwt.tenant_id`) es absoluto. Para este RF, el cálculo se hace offline en una base de datos secundaria especializada en BI, garantizando que un error en el código de aplicación no filtre datos de la competencia.

## 14. Criterios de aceptación (BDD)
* **CA-01: Umbral de Privacidad Estadística (k-anonymity)**
  * *Given* que un usuario intenta filtrar el benchmarking a "Colegios Privados en la región X"
  * *When* la base de datos detecta que solo hay 3 colegios en esa intersección
  * *Then* la API debe denegar el acceso a esos datos específicos devolviendo un mensaje "Pocos datos para anonimizar. Amplíe su filtro", protegiendo a la competencia.
* **CA-02: Exactitud del Percentil**
  * *Given* que el colegio solicitante tiene una tasa de deserción del 5%
  * *When* la media nacional es 10% y el P90 es 2%
  * *Then* el UI debe interpretar correctamente que en Deserción, "Menos es Mejor" (Métrica Inversa), ubicándolo adecuadamente en un percentil alto positivo.
