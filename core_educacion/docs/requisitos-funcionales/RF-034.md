## 2. Descripción funcional
* **Descripción:** Requerimiento no funcional/funcional arquitectónico absoluto. EDUCACION OS no es un sistema monolítico cerrado. Toda la lógica de negocio (CRUDs, flujos, IA) se expone obligatoriamente como una API REST/GraphQL. Esto permite construir un "Marketplace de Plugins" donde EdTechs de terceros (ej. Duolingo, Khan Academy, herramientas de contabilidad locales) puedan conectarse e inyectar datos directamente al Gemelo Digital.
* **Objetivo:** Convertir el producto de un simple "SaaS" a una "Plataforma (PaaS/OS)". El sistema operativo de la educación debe tener un ecosistema de aplicaciones de terceros.
* **Alcance:** Endpoints Públicos, Emisión de API Keys por Tenant, Webhooks salientes, OAuth2 Server.
* **Actores:** Desarrolladores Third-Party (Integradores), Administrador de Tenant (Aprobador).

## 3. Contexto
* **Precondiciones:** 
  1. Todos los módulos internos consumen la misma API (Consumo Dogfooding).
  2. Autenticación y Autorización basada en Scopes (`read:students`, `write:grades`).
* **Disparador:** Un desarrollador externo crea una App en el portal de developers de EDUCACION OS.
* **Postcondiciones:** Generación de un `client_id` y `client_secret` (OAuth2).

## 6. Flujo funcional
### Flujo principal (OAuth2 / Plugin Installation)
1. Un proveedor de Juegos de Matemáticas (Tercero) quiere integrarse con un colegio (Tenant).
2. El proveedor pide al Director que "Instale su App".
3. El Director hace clic en un link de OAuth2: `https://educacion-os.com/oauth/authorize?client_id=123&scope=write:grades`.
4. El sistema muestra la pantalla de consentimiento: "MathApp quiere poder modificar notas en tu colegio. ¿Aceptas?".
5. El Director acepta. El sistema genera un Access Token y se lo envía a MathApp.
6. A partir de ahora, cuando un niño juega en MathApp, este llama a nuestra API `POST /api/v1/students/{id}/grades` inyectando la nota automáticamente en la plataforma principal.

### Flujos alternativos
* **FA-01: Webhooks Outbound (Event-Driven):** En lugar de que el tercero pregunte a la API a cada rato (Polling), el colegio configura un Webhook: "Cuando un alumno falte a clase (`STUDENT_ABSENT`), haz un POST a este servidor de Twilio externo para mandar un SMS personalizado".

### Flujos de excepción
* **FE-01: API Rate Limiting y Abuso:** Si un plugin defectuoso entra en un bucle infinito y llama a la API 10,000 veces por segundo, el API Gateway (Kong/Nginx) aplica Rate Limiting agresivo (HTTP 429 Too Many Requests), revoca temporalmente el token y alerta al administrador.

## 8. Reglas de negocio
* **RN-001 (Dogfooding Absoluto):** Prohibido crear lógicas en el Frontend Web (Next.js) que se comuniquen directo con la Base de Datos eludiendo la API (ej. Server Actions pesados que bypassen el REST/GraphQL). La App Web, App Móvil y los Plugins de 3ros DEBEN consumir exactamente la misma API. Si la API no lo puede hacer, la app tampoco.
* **RN-002 (Webhooks Seguros):** Todo Webhook saliente emitido por EDUCACION OS debe llevar una firma criptográfica (HMAC-SHA256) en los headers (ej. `x-educacion-signature`), para que el receptor pueda validar que el request no fue falsificado por un atacante.

## 9. Permisos y seguridad
* **Zero Trust:** Las API Keys creadas para integraciones NUNCA sobrepasan el contexto del Tenant que las autorizó. RLS es obligatorio en todas las consultas originadas por un API Token.
* **Rotación Obligatoria:** Las llaves expiran cada 180 días, forzando una rotación para evitar fugas de credenciales.

## 10. Persistencia
* **Tablas/Colecciones:** Almacenamiento tradicional Postgres. Redis para el control de cuotas de Rate Limiting.

## 11. Integraciones
* **API Documentation:** Swagger / OpenAPI 3.0 auto-generado por NestJS en `/api/docs`.

## 12. Auditoría
* `api_access_logs`: Cada vez que un Plugin modifica una nota, se guarda en el log: "Nota modificada por [Plugin MathApp] el dd/mm/aaaa", evitando que el profesor asuma la culpa de un error de software.

## 14. Criterios de aceptación (BDD)
* **CA-01: Enforcement de Scopes OAuth2**
  * *Given* un Plugin con Scope exclusivo de `read:attendance`
  * *When* el Plugin hace un request `POST /api/v1/students/grades`
  * *Then* la capa de Guards (NestJS) debe abortar con `HTTP 403 Forbidden` indicando "Scope Insuficiente".
* **CA-02: Generación Swagger Automática**
  * *Given* que un desarrollador añade un nuevo endpoint al Controller
  * *When* compila el proyecto y navega a `/api/docs`
  * *Then* la documentación OpenAPI debe reflejar el nuevo endpoint, sus DTOs (Tipos), y códigos de respuesta sin necesidad de escribir documentación a mano.
