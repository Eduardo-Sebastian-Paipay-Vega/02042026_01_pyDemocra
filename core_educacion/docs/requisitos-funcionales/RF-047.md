## 2. Descripción funcional
* **Descripción:** Incorporación del estándar `WebXR` y librerías 3D (`Three.js` / `@react-three/fiber`) para crear laboratorios de Física y Química que corren nativamente en el navegador (PC, Tablet o Lentes VR) sin instalar aplicaciones pesadas.
* **Objetivo:** Democratizar el acceso a laboratorios costosos. Un colegio rural sin recursos para microscopios reales puede acceder a un laboratorio de biología 3D fotorrealista a través de Chromebooks de bajo costo.
* **Alcance:** Motor de físicas 3D (Cannon.js), Interactividad de Objetos, Integración con xAPI (RF-041).
* **Actores:** Estudiante (Jugador), Motor 3D (Render).

## 3. Contexto
* **Precondiciones:** 
  1. Navegador compatible con WebGL2 / WebXR.
  2. Dispositivo con GPU acelerada (Integrada o dedicada).
* **Disparador:** El profesor asigna una tarea de "Laboratorio de Tiro Parabólico".
* **Postcondiciones:** El estudiante experimenta en 3D y la analítica envía el reporte a su Perfil Cognitivo.

## 6. Flujo funcional
### Flujo principal (Laboratorio de Química)
1. Juan abre la tarea "Mezcla de Ácidos". 
2. La interfaz HTML estándar desaparece (Pantalla Completa) y un elemento `<canvas>` carga un modelo 3D (GLTF) optimizado con compresión Draco.
3. Usando el mouse (o gafas Oculus Quest), Juan interactúa con un vaso de precipitados y vierte un compuesto virtual.
4. El motor de físicas calcula la reacción (Cambio de color, humo de partículas).
5. Cada interacción exitosa envía un evento xAPI silencioso: `{"verb": "interacted", "object": "beaker"}`.
6. Al finalizar el experimento, Juan pulsa "Salir" y recibe su nota automáticamente basada en los pasos que siguió en el espacio 3D.

### Flujos de excepción
* **FE-01: Dispositivo No Compatible / Gama Baja:** Si el dispositivo de Juan tiene menos de 2GB de RAM o no soporta WebGL, el sistema hace un "Graceful Degradation" (Degradación elegante) y le muestra una versión 2D interactiva simplificada (Canvas HTML5 regular) para garantizar el acceso a la educación.

## 8. Reglas de negocio
* **RN-001 (Optimización Extrema):** Por mandato arquitectónico, ningún modelo 3D (GLTF/GLB) puede superar los 15MB. Se debe usar compresión Meshopt o Draco para garantizar tiempos de carga menores a 3 segundos en redes de colegios públicos.
* **RN-002 (Cero Latencia en Backend):** La lógica de física colisional corre 100% en el cliente (Client-Side con WebAssembly) para evitar *Lag*. El servidor solo recibe validaciones finales asíncronas para evitar trampas.

## 9. Permisos y seguridad
* **Protección de Assets:** Los modelos 3D costosos (propiedad intelectual de EDUCACION OS) deben entregarse ofuscados o tras una validación estricta de CORS y Token, para evitar que competidores descarguen los `.glb` directamente.

## 10. Persistencia
* **Infraestructura:** Archivos pesados en AWS S3 distribuidos vía CloudFront CDN.

## 11. Integraciones
* **Librerías Frontend:** `three.js`, `@react-three/fiber`, `@react-three/drei`, `cannon-es`.

## 12. Auditoría
* Métrica "Time-to-Interactive" (TTI). Monitorear globalmente cuánto tarda el canvas 3D en cargar. Si supera 5 segundos en promedio, se requiere re-compresión de texturas.

## 13. Notificaciones
* Aviso inicial: "Esta actividad requiere aceleración por hardware. Recomendamos usar Wi-Fi".

## 14. Criterios de aceptación (BDD)
* **CA-01: Rendimiento (60 FPS)**
  * *Given* el entorno 3D cargado en un Chromebook estándar (Métrica mínima)
  * *When* el estudiante renderiza la escena compleja
  * *Then* el profiler de React-Three-Fiber debe mantener un frame rate estable por encima de 45-60 FPS para prevenir mareos en realidad virtual (VR Sickness).
* **CA-02: Captura Analítica (xAPI)**
  * *Given* que el usuario ensambla una molécula correctamente
  * *When* se detona el evento de éxito
  * *Then* el canvas debe enviar un payload xAPI 2.0 válido al LRS (RF-041) certificando la competencia científica, persistiendo el logro en el Perfil Cognitivo.

## 15. Casos de prueba relacionados
