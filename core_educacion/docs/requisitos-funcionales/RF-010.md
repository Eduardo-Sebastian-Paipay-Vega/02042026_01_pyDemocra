# RF-010: Sistema de Cobranza Preventiva y Recordatorios Multicanal

| Atributo | Detalle |

| **Módulo** | Facturación y Ecommerce B2B/B2C |

| **Prioridad** | Alta (Reducción de Morosidad) |

## 2. Descripción funcional
* **Descripción:** Un motor de automatización (workflow) que evalúa las fechas de vencimiento de las mensualidades/suscripciones de los estudiantes y ejecuta comunicaciones multicanal (Email, SMS, WhatsApp) preventivas (ej. 3 días antes), el mismo día, y posteriores (morosidad activa).
* **Objetivo:** Disminuir drásticamente la tasa de morosidad institucional automatizando el esfuerzo humano del departamento de cobranzas, actuando como un "Bot de Recaudación" inteligente y amable.
* **Alcance:** Motor de evaluación diaria, orquestación de envíos a APIs de mensajería (Twilio, Resend, Meta Cloud API).
* **Actores:** Sistema (Ejecutor), Estudiante/Apoderado (Receptor).

## 3. Contexto
* **Precondiciones:** 
  1. Cronjob del sistema configurado para correr a medianoche.
  2. Suscripciones o cuotas con `due_date` registradas en la tabla `installments` o `subscriptions`.
  3. Tenant configurado con integraciones de terceros (Credenciales de Twilio/WhatsApp).
* **Disparador:** Job calendarizado diario (`0 0 8 * * *` - 8:00 AM UTC).
* **Postcondiciones:** Mensajes encolados y enviados; registros en tabla `communication_logs` creados.

## 6. Flujo funcional
### Flujo principal (Job de Cobranza Diaria)
1. El Scheduler (NestJS BullMQ) dispara el `DailyCollectionJob`.
2. El sistema realiza una consulta optimizada para encontrar todas las cuotas (`installments`) no pagadas (`status = 'PENDING'`) agrupándolas por los umbrales de tiempo.
   - Umbral 1 (Preventivo): `due_date = TODAY + 3 days`
   - Umbral 2 (Día de pago): `due_date = TODAY`
   - Umbral 3 (Mora Inicial): `due_date = TODAY - 3 days`
   - Umbral 4 (Mora Crítica / Suspensión): `due_date < TODAY - 15 days`
3. Por cada registro, el sistema lee la configuración de canales del tenant (WhatsApp, Email o SMS).
4. El sistema inyecta datos dinámicos a las plantillas (Nombre del alumno, Monto, URL de Pago directo o Yape).
5. Se envía la instrucción a la cola de comunicaciones (para no ahogar la red).
6. Si un estudiante cae en el Umbral 4 (Mora Crítica), el sistema desactiva el acceso a sus cursos (Soft-lock).

### Flujos alternativos
* **FA-01: Bloqueo Gradual UI:** En el Umbral 3 (Mora inicial), no se bloquea al estudiante, pero cada vez que hace login, el Dashboard levanta un Modal Ineludible ("Tienes un pago pendiente") que puede saltar tras 10 segundos, induciendo la fricción.

### Flujos de excepción
* **FE-01: Exclusión manual (Indulto):** Si un estudiante tiene un compromiso de pago arreglado con administración humana, tiene un flag `exclude_from_auto_collection = true`. El query principal los omite.

## 8. Reglas de negocio
* **RN-001 (Timezones):** El cálculo de `due_date` debe considerar estrictamente el huso horario (Timezone) del Tenant, para no enviar WhatsApps de cobranza a las 2:00 AM del país local.
* **RN-002 (Escalamiento a Apoderados):** Si el estudiante es menor de edad (flag `is_minor = true`), el mensaje de cobranza se enruta automáticamente a la tabla de `guardians` (Padres) y no al alumno.

## 9. Permisos y seguridad
* **Políticas RLS:** No aplicables directamente para los CronJobs del backend, los cuales operan con permisos administrativos (Service Role).
* **API Seguridad:** Las peticiones a Twilio/Meta API usan tokens cifrados configurados por tenant.

## 10. Persistencia
* **Tablas/Colecciones:** `installments`, `communication_logs`.
* **Rastreo de envíos:** Para evitar acosar al cliente con múltiples mensajes, cada envío se inserta en `communication_logs`. El query del Job verifica que NO exista un log idéntico de "Aviso Preventivo" enviado en las últimas 24 horas.

## 11. Integraciones
* **Mensajería Omnicanal:** Twilio (SMS), WhatsApp Cloud API (Meta), Resend/Sendgrid (Email).
* **Colas:** Redis + BullMQ (NestJS) para despachar miles de correos sin memory leaks.

## 12. Auditoría
* Visualización contable: El administrador del Tenant puede ver el "Historial de Contacto" de cada estudiante (Cuándo y qué canal fue usado para avisarle de su deuda).

## 13. Notificaciones
* Core de la funcionalidad (WhatsApp y Correo Electrónico).

## 14. Criterios de aceptación (BDD)
* **CA-01: Envío preciso al padre**
  * *Given* que un alumno moroso tiene el flag `is_minor = true`
  * *When* el Cron de cobranza ejecuta su flujo
  * *Then* el SMS/Email se envía exclusivamente a los datos de contacto del "Apoderado" relacionado.
* **CA-02: Auto-Bloqueo de Morosidad Crítica**
  * *Given* una deuda vencida por más de 15 días
  * *When* se cruza el umbral nocturno
  * *Then* el sistema marca la matrícula como `SUSPENDED_PAYMENT` impidiendo el acceso a los cursos, pero dejando abierto el portal de facturación.

## 15. Casos de prueba relacionados
