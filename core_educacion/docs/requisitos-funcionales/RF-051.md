## 2. Descripción funcional
* **Descripción:** EDUCACION OS no puede programar cada funcionalidad educativa del mundo. Para escalar, se abre como una plataforma (Platform as a Service - PaaS). Terceros (EdTech Startups) pueden crear "Plugins" o "Mini-Apps" que se instalan dentro del sistema del colegio (Ej. Un plugin de "Ajedrez Matemático").
* **Objetivo:** Convertir el sistema en el "Shopify de la Educación". Los directores pueden entrar a la *EDUCIA App Store* e instalar extensiones en su colegio con un clic.
* **Alcance:** SDK para desarrolladores, Sistema de Sandboxing (Iframe/WebComponents), App Store UI.
* **Actores:** Developer Externo (Creador), Director (Instalador), EDUCACION OS (Host).

## 3. Contexto
* **Precondiciones:** 
  1. RF-034 (OAuth2 y Autenticación de Máquina a Máquina).
  2. Aislamiento estricto de seguridad para iframes (Content Security Policy).
* **Disparador:** El Director instala el plugin "Mathletics" en la tienda de su Tenant.
* **Postcondiciones:** El plugin aparece en el menú lateral de los alumnos y puede leer/escribir notas según los *Scopes* aprobados.

## 6. Flujo funcional
### Flujo principal (Instalación y Ejecución de Plugin)
1. El Director navega a la "App Store" de EDUCACION OS y selecciona "Duolingo for Schools".
2. Hace clic en "Instalar". El sistema le advierte: *"Este plugin solicita acceso de LECTURA a las notas y ESCRITURA al Ledger de Tokens"*.
3. El Director acepta. El sistema genera credenciales OAuth2 y asocia el `plugin_id` al `tenant_id`.
4. El lunes, el alumno entra a la plataforma. En el menú lateral ahora aparece "Duolingo".
5. Al hacer clic, se abre un `<iframe>` incrustado. EDUCACION OS le inyecta un JWT firmado con los datos del alumno (SSO silencioso).
6. El alumno juega en Duolingo. Al ganar, el backend de Duolingo hace un POST al API de EDUCACION OS (usando su `client_secret`) y le regala 50 Tokens al alumno (RF-036).

### Flujos de excepción
* **FE-01: Exceso de Privilegios (Scope Violation):** Si el plugin de Ajedrez (que solo pidió permisos para leer el nombre del alumno) intenta borrar una nota llamando al endpoint `DELETE /api/v1/grades`, el API Gateway (Kong/NestJS) lo bloquea con HTTP 403 Forbidden, asegurando el aislamiento.

## 8. Reglas de negocio
* **RN-001 (Micro-Frontends):** Los plugins que renderizan UI dentro de EDUCACION OS deben cargarse dentro de Iframes con sandboxing estricto (`sandbox="allow-scripts allow-same-origin"`) para prevenir ataques de Cross-Site Scripting (XSS) contra la sesión del usuario principal.
* **RN-002 (Revocación Instantánea):** Si el Director desinstala el plugin, todos sus tokens de acceso (JWTs) se invalidan instantáneamente en Redis, cortando el acceso de la app externa a los datos del colegio en milisegundos.

## 9. Permisos y seguridad
* **Revisión Manual (Store Review):** Antes de que un plugin externo aparezca en la tienda pública para todos los colegios, debe pasar una auditoría de seguridad manual (SAST/DAST) por parte de los ingenieros de EDUCACION OS (Igual que el App Store de Apple).

## 10. Persistencia
* **Tablas/Colecciones:** Postgres.

## 11. Integraciones
* **Gateway API:** Kong API Gateway o AWS API Gateway para manejar Rate Limiting y validación de JWT a escala comercial.

## 12. Auditoría
* Monitoreo de "Data Egress" (Salida de datos). Si un plugin empieza a descargar masivamente la base de datos de estudiantes (Data Exfiltration), el sistema corta el acceso y alerta al Oficial de Privacidad.

## 13. Notificaciones
* Aviso a profesores: "El Director ha instalado la nueva herramienta 'Simulador de Física 3D' en sus aulas".

## 14. Criterios de aceptación (BDD)
* **CA-01: Sandboxing de UI**
  * *Given* un plugin instalado que contiene código JavaScript malicioso (ej. `parent.window.document.cookie`)
  * *When* el alumno abre el plugin en el iframe
  * *Then* el navegador debe bloquear el acceso al DOM padre, previniendo el robo de la sesión, gracias a las políticas CSP.
* **CA-02: Rate Limiting Externo**
  * *Given* una app externa mal optimizada
  * *When* lanza 5,000 requests por segundo al API de EDUCACION OS
  * *Then* el API Gateway debe aplicar Rate Limiting (ej. máximo 50 req/sec por Client_ID) y devolver HTTP 429 Too Many Requests, protegiendo al núcleo del sistema.

## 15. Casos de prueba relacionados
