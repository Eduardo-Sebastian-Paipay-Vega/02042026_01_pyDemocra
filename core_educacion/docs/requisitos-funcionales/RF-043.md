## 2. Descripción funcional
* **Descripción:** Arquitectura basada en microservicios e infraestructura como código (IaC) que permite al sistema monitorear su propio estrés (CPU, RAM, Conexiones a DB). Ante picos predecibles (ej. Exámenes bimestrales simultáneos a las 10:00 AM), el sistema aprovisiona automáticamente nuevos contenedores (Pods) y réplicas de solo lectura en la Base de Datos sin intervención humana.
* **Objetivo:** Garantizar que la plataforma jamás se cuelgue durante un examen importante. El tiempo de inactividad (Downtime) en colegios B2B destruye la confianza y genera rescisiones de contrato.
* **Alcance:** Kubernetes (K8s) Horizontal Pod Autoscaler (HPA), Postgres Connection Pooling, Caché distribuida.
* **Actores:** Sistema (Monitor HPA), Base de Datos (Pooler).

## 3. Contexto
* **Precondiciones:** 
  1. Aplicación Dockerizada (Node.js/NestJS) corriendo en Kubernetes.
  2. Métricas exportadas a Prometheus.
* **Disparador:** CPU de los Pods supera el 75% o las conexiones concurrentes a la DB superan el umbral seguro.
* **Postcondiciones:** Escalado horizontal ejecutado (Nuevos nodos levantados en < 1 min).

## 6. Flujo funcional
### Flujo principal (Pico de Tráfico Académico)
1. Lunes 08:00 AM. 5,000 alumnos inician sesión al mismo tiempo para su primera clase.
2. El Ingress Controller (Nginx/Traefik) detecta un salto de 100 RPS a 5,000 RPS.
3. El Horizontal Pod Autoscaler (HPA) de Kubernetes detecta que el CPU promedio de los 3 pods actuales de `api-server` cruzó el 75%.
4. HPA solicita al Cloud Provider (AWS EKS / GCP GKE) aprovisionar 10 pods adicionales.
5. Para proteger la base de datos PostgreSQL de un "Connection Exhaustion" (Demasiadas conexiones simultáneas), **PgBouncer** (Connection Pooler) multiplexa los miles de requests entrantes en un pool fijo de 100 conexiones físicas a la DB.
6. A las 12:00 PM, el tráfico baja. El HPA destruye los 10 pods extra para ahorrar costos de servidor (Scale-to-Zero capability).

### Flujos alternativos
* **FA-01: Fallback a Caché (Circuit Breaker):** Si PostgreSQL colapsa pese a todo, el Circuit Breaker de NestJS se abre. Las consultas de lectura (ej. "Ver mi horario") se sirven inmediatamente desde Redis (Caché Stale) devolviendo HTTP 203 (Non-Authoritative Info) en vez de un humillante HTTP 500, permitiendo que la App móvil siga funcionando.

## 8. Reglas de negocio
* **RN-001 (Read-Write Separation):** Todas las consultas HTTP `GET` deben ser enrutadas por Prisma/TypeORM hacia las Réplicas de Solo Lectura (Read Replicas). Todos los `POST/PUT/PATCH` van al Nodo Master (Writer). Esto triplica la capacidad de carga del sistema sin modificar lógica de negocio.
* **RN-002 (Stateless Core):** El backend de NestJS debe ser 100% Stateless. Prohibido guardar sesiones o archivos en el disco duro local del contenedor, todo va a Redis o S3. Esto permite destruir y crear contenedores a voluntad sin pérdida de datos.

## 9. Permisos y seguridad
* **DDoS Protection:** Capa de Rate Limiting por IP (Nginx) y WAF (Web Application Firewall - Cloudflare) para distinguir entre "Muchos alumnos legítimos" y un "Ataque de Denegación de Servicio".

## 14. Criterios de aceptación (BDD)
* **CA-01: Autoescalado bajo Carga**
  * *Given* un entorno K8s configurado con HPA
  * *When* se inyecta carga sintética (ej. K6 o JMeter) simulando 10,000 RPS sostenidos
  * *Then* la infraestructura debe detectar la carga en < 15 segundos y provisionar nuevos Pods hasta estabilizar el CPU por debajo del 70%, sin abortar peticiones (HTTP 500 < 0.1%).
* **CA-02: Protección de Conexiones DB**
  * *Given* 50 Pods de backend activos
  * *When* cada Pod intenta abrir 10 conexiones simultáneas a la Base de Datos
  * *Then* PgBouncer debe encolar las transacciones y multiplexarlas sin superar el `max_connections` del motor PostgreSQL, previniendo el crash del motor (OOM).

## 15. Casos de prueba relacionados
* `TC-RF043-01`: Chaos Engineering (Chaos Monkey). Simular la muerte repentina (Kill -9) del Pod de la Base de Datos Master. Verificar que el Failover Automático promociona a una Réplica a Master en < 30 segundos sin intervención humana.
