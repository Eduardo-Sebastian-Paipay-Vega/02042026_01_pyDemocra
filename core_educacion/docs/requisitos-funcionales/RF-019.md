## 2. Descripción funcional
* **Descripción:** Módulo genérico (Utility Service) accesible desde cualquier tabla interactiva (DataGrid) del sistema que permite a los usuarios exportar su vista actual (con filtros aplicados) a formatos estándar (CSV para integración, Excel para edición humana, PDF para presentación).
* **Objetivo:** Evitar la sensación de "Secuestro de Datos" (Data Lock-in). Permitir al personal administrativo manipular la información en Excel si lo requieren.
* **Alcance:** Exportación de listas (Estudiantes, Notas, Facturas). Renderizado de celdas según tipo de dato, y protección contra inyecciones CSV.
* **Actores:** Cualquier Usuario con rol de lectura sobre listas (Docente, Admin).

## 3. Contexto
* **Precondiciones:** 
  1. Tabla de datos renderizada en el frontend (React Table).
  2. Parámetros de filtro/ordenación (State) conocidos.
* **Disparador:** El usuario hace clic en "Exportar -> Excel".
* **Postcondiciones:** Archivo descargado en el navegador local del usuario.

## 4. Entradas
| Parámetro | Tipo | Obligatorio | Validaciones |
| :--- | :--- | :---: | :--- |
| `entity` | VARCHAR | Sí | Entidad a exportar (ej. `enrollments`). |
| `filters` | JSON | Sí | Filtros activos en UI (ej. `{ grade: "5", status: "active" }`). |
| `format` | ENUM | Sí | `CSV`, `XLSX`, `PDF`. |
| `columns` | ARRAY | No | Sub-lista de columnas visibles a exportar. |

## 5. Salidas
| Resultado / Campo | Tipo / Estado | Mensaje |
| :--- | :--- | :--- |
| `file_stream` | Blob (Buffer)| Flujo binario con el header `Content-Disposition: attachment`. |
| `413 Payload Too Large`| HTTP Error | Bloqueo si intenta exportar todo un histórico gigante síncronamente. |

## 6. Flujo funcional
### Flujo principal (Exportación Rápida CSV/XLSX)
1. El Frontend despacha un GET al endpoint genérico `/api/v1/export/:entity` adjuntando los Query Params de filtros.
2. NestJS valida los permisos del rol del usuario sobre esa entidad (Autorización).
3. (Streaming): Para no tumbar la memoria RAM del servidor con millones de filas, se abre un Query Stream/Cursor con Postgres.
4. Se transfiere el flujo a un generador (ej. `exceljs` o `csv-stringify`).
5. Se aplican transformaciones de celda (ej. Booleanos a "Sí/No", Fechas a formato local del tenant).
6. El stream resultante se enchufa (Pipes) directamente al response HTTP (Streaming response).
7. El navegador inicia la descarga inmediatamente, sin esperar a que todo se cargue en la RAM del servidor.

### Flujos alternativos
* **FA-01: Exportación Asíncrona (Carga Masiva):** Si el query detecta que retornará > 50,000 registros, NestJS aborta el stream síncrono y devuelve un `202 Accepted`. Se delega el trabajo a BullMQ. El Worker generará el archivo, lo subirá a Supabase Storage, y enviará una notificación con el Link de Descarga cuando acabe.

### Flujos de excepción
* **FE-01: CSV Injection Protection:** Si una celda de nombre de alumno contiene fórmulas como `=CMD|' /C calc'!A0`, Excel podría ejecutarlas (RCE Vulnerability). El motor de exportación sanitiza agregando una comilla simple (`'`) al inicio de campos conflictivos.

## 7. Objeto / Entidad (Modelo de Datos)
No aplica modelo de datos físico permanente. 
* **Tablas volátiles:** Si usa generación asíncrona, guarda URLs temporales en la tabla `user_exports` con un TTL (Time to Live) de 24 horas.

## 8. Reglas de negocio
* **RN-001 (Enmascaramiento de Datos):** La exportación respeta las mismas reglas RLS que la UI. Si un profesor solo ve a sus 30 alumnos en pantalla, el export no puede hacer bypass a RLS y descargar los 500 alumnos del colegio. (El token JWT se pasa directo al query).

## 9. Permisos y seguridad
* **Defensa contra Data Exfiltration:** Se aplican Rate Limits estrictos a endpoints de exportación (ej. Máximo 5 descargas por minuto por IP/Usuario) para alertar si un empleado intenta descargar masivamente toda la base de datos de la escuela (Amenaza Interna / Insider Threat).

## 10. Persistencia
* **Rendimiento:** El uso de PostgreSQL Cursors (`node-pg` cursor) es mandatorio para prevenir `Heap Out Of Memory` (OOM) en el contenedor de Node.js.

## 11. Integraciones
* Librerías Core: `exceljs` para XLSX, `pdfmake` (o Puppeteer) para PDF estéticos, Native Node Streams para CSV.

## 12. Auditoría
* Toda petición a `/export/*` se registra en `security_audit_logs` con la Entidad, Cantidad de Filas Exportadas y el Usuario que lo hizo, vital para el cumplimiento de GDPR en caso de fuga de datos.

## 13. Notificaciones
* Solo en caso de Exportación Asíncrona (Descarga masiva).

## 14. Criterios de aceptación (BDD)
* **CA-01: Rendimiento en Streaming Constante**
  * *Given* una solicitud de exportación de 20,000 filas a CSV
  * *When* el servidor procesa la petición
  * *Then* la memoria RAM del contenedor de Node.js no debe subir más de 50MB (Spike limit) ya que los datos deben fluir en Chunked Transfer Encoding directo al cliente.
* **CA-02: Sanitización de Fórmulas Maliciosas (CSV Injection)**
  * *Given* un alumno malicioso que se llama `=+cmd|' /C...`
  * *When* el profesor exporta la lista en Excel o CSV
  * *Then* el archivo generado neutraliza la fórmula forzándola a ser texto plano, protegiendo la computadora del profesor.

## 15. Casos de prueba relacionados
* `TC-RF019-01`: Vulnerability Scan contra CSV Injection.
* `TC-RF019-02`: Memory Profiling (Heap Snapshot) exportando grandes volúmenes de datos en concurrencia.
