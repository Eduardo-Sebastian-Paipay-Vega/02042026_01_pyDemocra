## 2. Descripción funcional
* **Descripción:** Sistema de cobros que permite a los Tenants vender cursos, recibir pagos de mensualidades (SaaS educativo) y vender material, mediante pasarelas internacionales (Stripe) y locales de Latam (Yape/Plin vía integradores como Culqi o Niubiz).
* **Objetivo:** Automatizar la recaudación monetaria, conciliar los pagos automáticamente con las matrículas y reducir la morosidad mediante cargos recurrentes (suscripciones).
* **Alcance:** Checkouts en la UI, manejo de Webhooks, asignación de accesos tras pago exitoso.
* **Actores:** Comprador (Estudiante/Tutor), Sistema (Conciliador), Pasarela Externa (Stripe/Culqi).

## 3. Contexto
* **Precondiciones:** 
  1. El Tenant ha configurado sus credenciales de pasarela (Stripe Connect o Keys directas).
  2. El curso o servicio tiene un precio configurado en `products`.
* **Disparador:** El estudiante hace clic en "Comprar" o "Pagar Mensualidad".
* **Postcondiciones:** Si el pago es exitoso (Webhook recibido), se matricula al estudiante automáticamente y se genera un recibo/invoice.

## 6. Flujo funcional
### Flujo principal (Cobro con Tarjeta)
1. El usuario selecciona el curso y procede al Checkout.
2. El frontend (Stripe Elements / Culqi UI) tokeniza la tarjeta directamente con la pasarela.
3. El frontend envía el `paymentMethodToken` a NestJS.
4. NestJS recupera el secreto de pasarela configurado por el Tenant y valida el precio original desde la DB.
5. NestJS crea un `PaymentIntent` en Stripe solicitando el cobro.
6. Stripe responde (éxito o requiere 3D Secure).
7. Si es éxito, NestJS registra la `transaction`, inyecta la `enrollment` (matrícula) y avisa al UI para mostrar página de éxito.

### Flujos alternativos
* **FA-01: Pagos asíncronos (Yape/Billeteras locales):** Se genera un QR. El sistema queda a la espera de un Webhook desde la pasarela (ej. Izipay/Culqi) que confirmará el pago en minutos u horas. Al recibir el Webhook, se aprueba la matrícula.

### Flujos de excepción
* **FE-01: Caída de Webhook (Desincronización):** Si el usuario pagó pero el Webhook de Stripe falla (red), un Cron Job conciliador revisa cada hora los "Pagos Pendientes" llamando a la API de Stripe para sincronizar el estado real de la transacción.

## 8. Reglas de negocio
* **RN-001 (Zero-Trust Pricing):** Jamás confiar en el parámetro `amount` enviado desde el frontend. El precio siempre se consulta a la base de datos `products` en el backend justo antes de cobrar.
* **RN-002 (Idempotencia de Webhooks):** Los Webhooks de la pasarela pueden llegar duplicados. La API receptora de Webhooks (`/api/v1/webhooks/stripe`) debe usar la firma de evento de Stripe (`Stripe-Signature`) y asegurar idempotencia para no crear matrículas dobles.

## 9. Permisos y seguridad
* **Seguridad Financiera:** El sistema (NestJS y Base de Datos) NUNCA almacena ni toca números de tarjetas de crédito completos (`PAN`), fechas de vencimiento, ni CVV. Solo almacena "Tokens" para cumplir la normativa PCI-DSS.
* **Firma de Webhooks:** Rechazo automático de cualquier request al endpoint de Webhook que no contenga una firma HMAC válida validada con el Endpoint Secret.

## 10. Persistencia
* **Tablas/Colecciones:** `transactions`, `enrollments`.
* **Transacciones (DB):** El insert del pago y de la matrícula operan bajo `BEGIN ... COMMIT` para evitar estudiantes con cobro pero sin curso asignado.

## 11. Integraciones
* **APIs externas:** Stripe API (Global), Culqi/Niubiz API (Latam / Yape / Plin).

## 14. Criterios de aceptación (BDD)
* **CA-01: Verificación de Precios (Anti-spoofing)**
  * *Given* que un curso cuesta 100 USD
  * *When* el cliente (por red local o postman) envía un request de cobro alterado de `amount: 10`
  * *Then* la API de NestJS rechaza el cobro, registra la IP en auditoría de fraude y devuelve un error 400.
* **CA-02: Recepción Idempotente**
  * *Given* que el webhook "payment_intent.succeeded" llega dos veces por fallos de red en 500ms
  * *When* el sistema procesa ambas peticiones
  * *Then* el sistema procesa la primera creando la matrícula y la segunda devuelve `200 OK` (por idempotencia) pero NO crea una segunda matrícula.
