## 2. Descripción funcional
* **Descripción:** Asistente IA embebido en la vista del profesor que asume dos tareas de alto desgaste: 1) Proponer retroalimentación escrita cualitativa basada en la rúbrica y el texto del alumno (Feedback), y 2) Generar variantes únicas de exámenes para cada alumno basado en el mismo temario (Anti-Copia).
* **Objetivo:** Reducir un 60% la carga administrativa del profesor, permitiéndole ser un "Revisor" en lugar de un "Redactor".
* **Alcance:** Interfaz de corrección de tareas. Generador de bancos de preguntas dinámicos.
* **Actores:** Docente (Operador/Revisor), Sistema LLM (Generador).

## 3. Contexto
* **Precondiciones:** 
  1. El alumno subió un ensayo (Texto/PDF transcrito).
  2. El profesor tiene una Rúbrica definida.
* **Disparador:** El profesor hace clic en "Auto-evaluar con Copiloto".
* **Postcondiciones:** Generación de un borrador de feedback. El docente lo edita/aprueba y se guarda.

## 4. Entradas

| Resultado / Campo | Tipo / Estado | Mensaje |

## 6. Flujo funcional
### Flujo principal (Feedback Generativo)
1. El docente abre la entrega de Juan Pérez.
2. Presiona "Generar Feedback".
3. NestJS orquesta un flujo RAG. Extrae el PDF, usa OCR si es necesario, y ensambla el prompt: *"Evalúa este texto usando la siguiente rúbrica..."*.
4. Llama a la API (OpenAI GPT-4o o Claude 3.5). 
5. Se muestra el `draft_feedback` en modo *Streaming* (efecto máquina de escribir) en un TextArea en la UI.
6. El profesor lee, edita lo que no le gusta, selecciona el puntaje real y presiona "Guardar y Enviar al Alumno".

### Flujos alternativos
* **FA-01: Exámenes Únicos (Generador Anti-Copia):** En vez de crear un PDF estático, el Copiloto crea un "Esqueleto" de examen. Cuando los alumnos entran, el LLM permuta las preguntas, cambia los números de los problemas de matemáticas, y altera el orden, generando 30 exámenes matemáticamente equivalentes pero distintos en texto.

### Flujos de excepción
* **FE-01: Alucinaciones de Puntaje:** Si la IA sugiere que el alumno sacó "120/100" (Alucinación matemática), la capa Zod de NestJS rechaza el payload estructurado y muestra al docente "IA no pudo determinar el puntaje, asigne manualmente".

## 8. Reglas de negocio
* **RN-001 (Transparencia):** Todo feedback generado con ayuda de IA y enviado al alumno debe llevar una pequeña marca de agua sutil (ej. "Revisado por Profesor X con asistencia de Copiloto IA") para mantener la confianza ética.
* **RN-002 (Costo por Token):** Dado que llamadas LLM masivas son caras, el tenant tiene un "Pool de Tokens" mensual. Si se agota, el botón de Copiloto se desactiva (Upselling).

## 9. Permisos y seguridad
* **Protección IP:** Los ensayos de los estudiantes enviados al modelo LLM no deben ser usados para entrenar los modelos base. Es obligatorio usar APIs comerciales con cláusula de Privacidad (Zero Data Retention) como OpenAI Enterprise o Azure OpenAI.

## 10. Persistencia
* **Tablas/Colecciones:** Almacenamiento directo en la tabla de revisiones (`submission_reviews`).

## 11. Integraciones
* **LLM Provider:** Integración oficial vía Vercel AI SDK o LangChain JS.

## 12. Auditoría
* Se registra el ahorro de tiempo. Si un docente se demora 10 minutos en corregir un ensayo a mano, y 2 minutos con el Copiloto, se registra el ROI (Return on Investment) para justificar la licencia del software al colegio.

## 13. Notificaciones
* Estándar (El alumno recibe su nota).

## 14. Criterios de aceptación (BDD)
* **CA-01: Generación en Streaming**
  * *Given* que el LLM tarda 10 segundos en procesar
  * *When* el profesor invoca al copiloto
  * *Then* la interfaz no debe bloquearse (Loader infinito), sino mostrar los tokens apareciendo en tiempo real vía Server Sent Events (SSE).
* **CA-02: Control de Edición Humana**
  * *Given* un borrador generado por IA
  * *When* el profesor presiona "Enviar sin leer" (Mismo timestamp de generado y enviado)
  * *Then* el sistema levanta un Warning exigiendo que al menos haga focus o modifique 1 carácter del textarea para forzar revisión humana (Mitigación de pereza docente).
