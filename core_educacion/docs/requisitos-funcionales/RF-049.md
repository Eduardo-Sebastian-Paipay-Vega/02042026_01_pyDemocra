## 2. Descripción funcional
* **Descripción:** Un módulo Enterprise para colegios que entregan Tablets o Chromebooks a sus alumnos. EDUCACION OS actúa como un MDM (Mobile Device Management). El departamento de IT del colegio puede bloquear aplicaciones no educativas, rastrear dispositivos perdidos, instalar actualizaciones OTA (Over-The-Air) y forzar el "Kiosk Mode" (Pantalla bloqueada) durante los exámenes globales.
* **Objetivo:** Ofrecer una solución "Todo en uno". Los colegios no necesitan pagar un costoso software de MDM (como Jamf o Google Workspace MDM) aparte del LMS; EDUCACION OS domina tanto el software como el hardware del alumno.
* **Alcance:** Control de Políticas (GPO/Profiles), Modo Kiosko, Borrado Remoto (Wipe).
* **Actores:** Administrador IT (Emisor), Dispositivo Físico del Alumno (Receptor).

## 3. Contexto
* **Precondiciones:** 
  1. El dispositivo (iPad, Android, Chromebook) fue "Enrolado" previamente usando perfiles de configuración MDM oficiales del SO.
* **Disparador:** El Administrador IT aplica una política global (Ej. "Bloquear YouTube de 8 AM a 2 PM").
* **Postcondiciones:** El dispositivo recibe el Payload de configuración y aplica la restricción a nivel Kernel/SO.

## 6. Flujo funcional
### Flujo principal (Activación de Examen - Kiosk Mode)
1. Es hora del Examen Final Nacional (RF-011).
2. El Director presiona el botón "Activar Modo Examen Severo" para todo el 5to año.
3. El servidor MDM de EDUCACION OS envía un comando APNs (Apple) / FCM (Google) a las 200 tablets de los alumnos.
4. Las tablets entran instantáneamente en "Single App Mode" (Modo Kiosko).
5. Los alumnos no pueden salir de la app de EDUCACION OS, no pueden abrir Google, ni ver notificaciones de WhatsApp. El botón de "Inicio" del hardware queda deshabilitado.
6. Al entregar el examen, el servidor envía el comando de liberación y las tablets vuelven a la normalidad.

### Flujos de excepción
* **FE-01: Dispositivo Perdido / Robado:** Si un alumno reporta su iPad escolar como robado, el Admin IT emite un comando `REMOTE_WIPE`. La próxima vez que el dispositivo se conecte a Internet, el procesador criptográfico destruye las llaves de encriptación (Crypto-Erase) en milisegundos, borrando toda la data escolar.

## 8. Reglas de negocio
* **RN-001 (BYOD Privacy - Bring Your Own Device):** Si el dispositivo es propiedad privada del alumno (BYOD), el MDM solo puede instalar un "Work Profile" aislado (Contenedor). El colegio no tiene permisos técnicos para leer los SMS privados, fotos o ubicación fuera del horario escolar, cumpliendo estrictas leyes de privacidad.
* **RN-002 (Failsafe Kiosk):** Un comando de Modo Kiosko DEBE llevar un "Timeout" embebido (Ej. 3 horas). Si la tablet pierde internet y no recibe el comando de "Desbloqueo", se auto-libera al expirar el tiempo para no "brickear" (Inutilizar) el dispositivo accidentalmente.

## 9. Permisos y seguridad
* **Certificados MDM:** El backend debe comunicarse mediante certificados mutuales mTLS altamente seguros con los servidores de Apple (APNs) y Google (Android Enterprise) para evitar *Man-in-the-Middle* attacks donde un atacante tome control de la flota de colegios.

## 10. Persistencia
* **Tablas/Colecciones:** Postgres para inventario, Redis para encolado rápido de comandos a flotas masivas (BullMQ).

## 11. Integraciones
* **Protocolos Nativos:** Apple MDM Protocol, Android Management API, ChromeOS Policy API.

## 12. Auditoría
* Registro inmutable de cada administrador que ordena un Bloqueo o Borrado Remoto, incluyendo su IP, justificación y Timestamp, para evitar abusos de poder del personal de IT.

## 13. Notificaciones
* Aviso en Pantalla del Dispositivo: "Este dispositivo está siendo administrado por la Institución XYZ".

## 14. Criterios de aceptación (BDD)
* **CA-01: Entrega de Comando Over-The-Air**
  * *Given* una flota de 1,000 dispositivos enrolados
  * *When* el Admin IT dispara un comando de bloqueo de cámara web
  * *Then* el 95% de los dispositivos conectados deben reportar `ACKNOWLEDGED` (Acuse de recibo) en menos de 60 segundos, aplicando el perfil localmente.
* **CA-02: Garantía Anti-Cheat (Kiosk)**
  * *Given* el modo Kiosko activo
  * *When* el estudiante intenta hacer un "Swipe" hacia arriba, cambiar de aplicación, o reiniciar la tablet
  * *Then* el SO bloquea la acción a nivel Kernel y la app de examen permanece anclada al 100% de la pantalla.

## 15. Casos de prueba relacionados
* `TC-RF049-01`: Probar la revocación de un certificado de MDM. Si el certificado expira, el backend debe avisar con 30 días de anticipación para evitar que el colegio pierda el control total de sus miles de tablets de un día para otro.
