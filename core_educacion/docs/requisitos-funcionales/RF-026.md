## 2. Descripción funcional
* **Descripción:** Implementación de un "Cerebro Institucional". En lugar de tener PDFs, videos y foros aislados, el sistema extrae entidades (Conceptos, Autores, Fórmulas) y los relaciona en un Grafo de Conocimiento (Knowledge Graph). Permite que la IA y los estudiantes entiendan cómo el tema "Vectores" de Física está conectado con "Trigonometría" en Matemáticas.
* **Objetivo:** Destruir los silos de información. Permitir a los agentes de IA (RAG) dar respuestas precisas basadas en la ontología exacta del colegio, encontrando relaciones ocultas que una búsqueda vectorial clásica (Cosine Similarity) omitiría.
* **Alcance:** Pipeline de extracción de entidades (NLP), almacenamiento en motor de grafos, API de consulta de relaciones.
* **Actores:** Sistema NLP (Extractor), Estudiante (Consultor visual), IA (Consultor interno).

## 3. Contexto
* **Precondiciones:** 
  1. Repositorio de material del colegio con archivos (PDFs/Videos) subidos (RF-003).
  2. Motor de base de datos orientada a grafos activo (Neo4j o Apache Age en Postgres).
* **Disparador:** Un profesor sube un nuevo material de estudio al curso.
* **Postcondiciones:** Nodos y Aristas (Edges) creados/actualizados en el Knowledge Graph.

## 6. Flujo funcional
### Flujo principal (Construcción del Grafo)
1. El docente sube un apunte sobre "Células Eucariotas".
2. Un *Event Listener* dispara un Worker en background.
3. El Worker usa un LLM (ej. GPT-4o-mini con Structured Outputs) o un modelo de Named Entity Recognition (NER) como SpaCy para extraer Conceptos Clave y sus Relaciones (Tripletas: Sujeto-Predicado-Objeto).
4. El Worker ejecuta sentencias `Cypher` (Lenguaje de grafos) para hacer UPSERT de los Nodos en la base de datos (Neo4j o Memgraph).
5. Se crean las aristas (ej. `(Célula_Eucariota)-[:CONTIENE]->(Núcleo)`).
6. El nodo se enriquece con el `file_url` del documento original para referencias cruzadas.

### Flujos alternativos
* **FA-01: Graph-RAG (Retrieval-Augmented Generation):** Cuando un estudiante le pregunta al Copiloto (RF-023) "No entiendo la mitosis", la IA no solo busca texto similar, sino que navega el Grafo, descubre que la mitosis requiere entender el ADN, y formula una respuesta que trae el PDF exacto de ADN que el profesor subió hace 3 meses.

### Flujos de excepción
* **FE-01: Colisión de Entidades (Entity Resolution):** Si un documento habla de "Gravedad" y otro de "Fuerza Gravitatoria", el motor NLP debe usar embeddings para detectar que son lo mismo (Cosine similarity > 0.95) y fusionar (Merge) los nodos para no crear grafos dispersos y sucios.

## 8. Reglas de negocio
* **RN-001 (Multi-Tenancy en Grafos):** A diferencia de Postgres (donde el RLS es fácil), en Neo4j el aislamiento multitenant requiere usar Bases de Datos separadas por Tenant (si es Enterprise) o prefijar todos los IDs y Nodos con un `tenant_id` estricto en cada Query Cypher.
* **RN-002 (Ontología Escolar):** El grafo restringe las etiquetas de Nodos a una ontología finita (Subject, Topic, Concept, Material, Assessment, Person) para evitar que la IA cree basura (ej. Nodos con la palabra "El" o "Y").

## 9. Permisos y seguridad
* **Graph Traversal Limits:** Para evitar ataques de denegación de servicio (DoS) por consultas de grafos infinitas (`MATCH (n)-[*]->(m)`), el API Gateway impone un límite de "Profundidad máxima" (Max Depth = 3 saltos).

## 10. Persistencia
* **Tablas/Colecciones:** Memgraph (In-memory, super rápido) o Neo4j (Enterprise). Alternativamente, si no se quiere otra BD, usar la extensión `Apache AGE` sobre el mismo PostgreSQL.

## 11. Integraciones
* **Modelos NLP:** LangChain GraphExtractionChain o un pipeline de NLP en Python (SpaCy / GLiNER).

## 12. Auditoría
* Monitoreo de "Grafos Huérfanos" (Nodos desconectados del resto del currículo), indicando que un material subido no tiene relación con el sílabo oficial (Posible pérdida de tiempo del alumno).

## 14. Criterios de aceptación (BDD)
* **CA-01: Graph-RAG Querying**
  * *Given* que un usuario pregunta sobre el Concepto A
  * *When* el motor RAG busca contexto
  * *Then* debe extraer el Nodo A, y todos sus Nodos Vecinos de distancia 1, inyectando ese subgrafo como texto en el Prompt de OpenAI.
* **CA-02: Resolución de Entidades (Merge)**
  * *Given* que ya existe un Nodo `Biología` en el Tenant 1
  * *When* se procesa un nuevo documento que menciona `Biología`
  * *Then* no se debe crear un nuevo Nodo `Biología_2`, sino agregar una nueva arista `MENTIONED_IN` al Nodo existente, incrementando su peso (Centralidad del nodo).
